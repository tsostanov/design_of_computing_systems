## Что вставить в отчёт

### 1. Цель и оборудование

Возможная формулировка цели:

> Реализовать электронный уровень на STM32F427VIT6. Получать данные акселерометра по I2C, отображать направление на OLED и передавать показания на ПК через UART.

Укажите стенд SDK-1.1М, STM32CubeIDE 1.9.0, акселерометр и OLED. Модель датчика уточните по ответу `PING` или маркировке своего стенда: прошивка поддерживает LSM9DS0 и LSM9DS1.

| Параметр | Настройка в коде |
|---|---|
| I2C | I2C1, PB8 (SCL), PB9 (SDA), 400 кГц |
| UART | USART6, PC6 (TX), PC7 (RX), 115200 бит/с, 8N1 |
| Экран | OLED 128×64, адрес I2C `0x3c` |
| Опрос датчика | Каждые 20 мс |
| Обновление изображения и отправка `DATA` | Каждые 100 мс |
| Устаревшие данные | Сбрасываются после 500 мс без новых показаний |

### 2. Алгоритм

Можно использовать такое описание реализации:

> При запуске программа настраивает UART и I2C, начинает инициализацию дисплея и поиск датчика. В основном цикле она получает ускорения по трём осям, вычисляет координаты указателя, обрабатывает команды ПК и обновляет экран. В режиме HORIZ линия показывает горизонталь, а в режиме ARROW стрелка показывает направление вниз. Изображение передаётся на OLED по одной странице за проход цикла. Между передачами обслуживается UART. При ошибке датчика программа сбрасывает показания и повторяет инициализацию.

Для схемы алгоритма используйте последовательность: инициализация, проверка датчика, чтение ускорений, расчёт указателя, обработка UART, обновление экрана и отправка данных, следующий проход цикла. Действия с интервалами выполняются только при наступлении нужного времени.

### 4. Обмен с ПК

Команды заканчиваются переводом строки:

| Команда | Ответ |
|---|---|
| `PING` | `PONG LEVEL3 1 <имя датчика>` |
| `GET` | Текущий кадр `DATA` |
| `MODE HORIZ` | `OK MODE HORIZ` |
| `MODE ARROW` | `OK MODE ARROW` |

Формат кадра:

```text
DATA sequence ms mode ax ay az dx dy sensor_ok oled_ok
```

Здесь `sequence` является номером кадра, `ms` содержит время работы в миллисекундах, `ax`, `ay`, `az` содержат ускорения в mg, `dx`, `dy` задают смещение указателя. Признаки `sensor_ok` и `oled_ok` принимают значения `0` или `1`.

Пример формата, не результат измерения:

```text
DATA 1 100 HORIZ 0 0 1000 18 0 1 1
```
