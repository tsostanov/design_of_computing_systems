## Краткие условия

**ЛР №1 — GPIO.** Ввести кнопкой до восьми точек и тире. Короткое нажатие подтверждается жёлтым светодиодом, длинное — красным. После паузы введённая последовательность однократно проигрывается зелёным светодиодом. Реализованы собственный драйвер GPIO, антидребезг и неблокирующая работа по времени.

**ЛР №2 — UART.** Расшифровывать введённый кнопкой код Морзе и отправлять букву компьютеру. Принимать латинские буквы через UART и проигрывать их зелёным светодиодом, сохраняя до восьми ожидающих букв в очереди. Обслуживать ввод и проигрывание одновременно. Символом `+` переключать UART между опросом и прерываниями; скорость — 115200 бит/с. Первая часть реализована на HAL; для второй части выбран способ 2 — оконный симулятор с виртуальным COM-портом.

## Как открыть нужную лабораторную

Для просмотра выберите ссылку «Исходники» в таблице. Для скачивания этой версии на GitHub нажмите **Code → Download ZIP**.

Если репозиторий уже клонирован, можно получить отдельную папку нужной версии, не переключая текущий проект. Выполните из корня репозитория одну из команд:

```powershell
# Лабораторная работа №1
git worktree add --detach ../pvs-lab1 e7a9e4813b846f6feda4ed85eb60c893eca59def

# Лабораторная работа №2
git worktree add --detach ../pvs-lab2 605aa4c788a8af6bcc645205de5498fe3e30cacf
```

Это копии для просмотра и запуска сохранённых версий. Для дальнейшей разработки в такой папке сначала создайте ветку командой `git switch -c имя-ветки`.

В STM32CubeIDE выберите **File → Import → General → Existing Projects into Workspace**, укажите папку выбранной лабораторной и выполните **Project → Build Project**. Обе версии имеют имя проекта `test_f427`: для одновременного хранения в IDE используйте разные workspace. Загрузка на стенд выполняется через сохранённую конфигурацию **test_f427 Debug**, FTDI/JTAG и OpenOCD.

Подробные шаги загрузки, настройки PuTTY и запуска симулятора находятся в [инструкции ЛР №2](docs/LAB2.md).

## ЛР №3 — электронный уровень

Прошивка считывает ускорение по трём осям с LSM9DS0/LSM9DS1 через I²C1 (PB8 — SCL, PB9 — SDA, 400 кГц), отображает указатель на OLED и передаёт данные через USART6 (115200, 8N1). Режимы отображения: `HORIZ` и `ARROW`. Выбор и знаки осей задаются в `Core/Inc/level_config.h` и требуют проверки на реальном стенде.

Откройте проект в STM32CubeIDE, выполните Refresh и Build Project. По умолчанию выбран `LAB_NUMBER=3`. Загрузка использует сохранённую конфигурацию `test_f427 Debug`.

Клиент для ПК требует Python с Tkinter и зависимости из `client/requirements.txt`:

```powershell
python -m pip install -r client/requirements.txt
python -m client COM5
# Просмотр интерфейса с искусственными данными:
python -m client --demo
```

Замените `COM5` на порт стенда. Клиент показывает оси, состояние датчика и дисплея, переключает режим после подтверждения прошивкой и записывает обмен в локальный `level-uart.jsonl`.

Команды UART: `PING`, `GET`, `MODE HORIZ`, `MODE ARROW`, каждая завершается переводом строки. Прошивка отправляет кадры `DATA` с номером, временем, режимом, ускорениями в mg, координатами указателя и признаками исправности датчика/OLED.

Проверки без стенда (для C-тестов нужен GCC или переменная `CC` с путём к компилятору):

```powershell
python tests/run_level_tests.py
python tests/run_tests.py
```

Тесты проверяют драйверы через подставную шину, вычисления, протокол, обработку ошибок и клиент. Работа датчика, дисплея и ориентация осей на физическом стенде требуют отдельной проверки.
